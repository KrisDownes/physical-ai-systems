# Shared manipulation pilot: two-week work budget

This is a bounded research budget, not a schedule to wait through. Milestones: (1) preserve calibration and bottle evidence, focused prior-art review and task feasibility; (2) freeze interface and condition splits, collect contact-rich data and run training smoke; (3) train matched current-state and history predictors across seeds, evaluate prediction and paired closed-loop outcomes; (4) diagnose, checkpoint and decide whether an information-gathering extension is justified. At most two focused attempts per defect; after that fix, simplify, bypass, or defer.

## Status and bounded decisions

- Camera/tool calibration stays closed for the conditions in `TRANSFER_RESULTS.md`. Bottle remains a separate development environment: 42 mm median closure displacement, empty/wet feasibility unresolved, maximum-closure comparator joint-limit excursions, rigid miniature bottle and unvalidated friction proxy. No additional bottle tuning has been performed this cycle; lifting is deferred rather than counted as a successful held-out task.
- Initial free-box pushing and handled-slider pulling used the existing MuJoCo SO-101 model, cameras and joint controller. A marker on the pull slider was initially undetected because the old cyan threshold was too strict; a dedicated visible fiducial and threshold restored measured visibility. The marker is fixed to slider geometry and is not simulator truth. Both task inputs carry visibility masks.
- First free-box data collection had QACC/QVEL warnings. A second check at 2.5 ms found further warnings and implausible excursions even without warnings. Decision: **simplify** pushing to a guided slider and retain a separate physical handled-slider pull. The initial free-push and failed collection logs remain development data, not training. This narrows the tasks' physical diversity and does not prove transfer to free objects. No third task is fabricated.
- The existing Tinygrad 0.14 installation segfaulted during sandbox CUDA auto-detection. Forcing CPU exposed a missing clang toolchain; forcing GCC is incompatible with Tinygrad's compiler arguments. Decision: **bypass** framework setup for this small baseline using NumPy, with explicit gradients checked against finite differences. Tinygrad work is unchanged. The smoke test overfits eight transitions only to check plumbing, not research performance.

## Frozen protocol

`shared_protocol.json` fixes train/validation/test condition combinations and starting configurations before training. No held-out task family is claimed: both guided push and pull supply training trajectories, and bottle lift remains unverified. A later held-out task must be excluded from training, normalization, model selection and tuning. Physical parameters are evaluator/setup only. The shared predictor receives current visual x/y and finite-difference visual velocity, nominal FK tip xy, six joint angles, current visibility mask, and current action; the history variant also receives the prior three observation–action vectors. Fixed engineering scales are used, not fitted normalization. Missing positions are zeros with a mask; targets requiring a missing current or next detection are excluded from prediction fitting, while whole episodes/failures are retained.

The push uses the same green object detector as the prior task. The pull's visual fiducial is rigidly offset 45 mm from the handle, with known nominal geometry and its own detector; this is task-specific sensing/setup scaffolding shared by all controllers. Goals and setup procedures are supplied per task, and the learned model never receives the task label. The action is bounded x/y displacement, fixed pitch and wrist orientation, and a declared open/closed gripper target; this is not arbitrary 6-DoF or force control. All setup motion, settling and commands count against the 250-action/10-rad episode budgets. Physics-step self-collision and joint-limit checks are inherited; numerical warnings and implausible slider state are logged.

Hypothesis: recent interaction can improve observable next-state predictions and goal-directed task control on unseen physical settings. Comparison: conventional feedback, current-state predictor, history predictor, and identical history predictor with context frozen after three actions. Prediction and closed-loop outcomes are separate; frozen history creates a distribution shift. A one-step five-candidate action selector is deliberately simple; it has no learned exploration, adaptation weight updates, or privileged inputs. The model can fail because observations, training coverage, data volume, optimization or contact dynamics are insufficient; none alone proves a causal explanation.

A further validation check found the first guided-task data and partial evaluation had changed body mass/inertia without `mj_setConst`, leaving MuJoCo's derived subtree mass stale. Those outputs are retained as development only. The interface now invokes `mj_setConst`, and the subtree mass is checked against body mass. New condition values and starts were frozen in `shared_protocol.json` before replacement data collection; earlier inspected cases are not treated as final evaluation. See [MuJoCo simulation guidance](https://github.com/google-deepmind/mujoco/blob/main/doc/programming/simulation.rst), which marks mass and inertia updates safe with `mj_setConst`.

Milestones 1–4 completed for the bounded, simplified two-task pilot. Corrected data: 24 episodes, 180 training transitions; three seeds per predictor, 400 CPU updates each; 48 paired closed-loop episodes. All methods succeeded with the same action sequences, so no benefit from history or reason for probing was demonstrated. The full measured outcomes, frozen-context limitation, commands and next hypothesis are in `SHARED_RESULTS.md`. The task-family holdout and bottle lift remain deferred, so the research question about transfer across unseen task families remains unanswered.
